\section{Scope and evidence}
This planning phase began only after MHM2010 Correction Workbench 0.1.0 was
posted for download. No T4 implementation, live query, instrument adjustment
or remote repository push was performed.

The reviewed repository's T4 examples use IPv4 UDP, example port 14000, the
command \texttt{MONIT;}\ followed by CRLF, and a dollar-prefixed 113-hex-character
payload \codecite. Safran's datasheet describes Ethernet monitoring and remote
functions, but not the complete MONIT protocol or the synthesizer/drift control
transfer equations \datacite. The AB monitor source supplies useful qtpy and
pyqtgraph patterns for bounded live previews and in-place updates \repocite.

The reviewed commit is
\texttt{9682a2ffbcd0b0df6612d4aef3619d7bdaf6cc66}. The T4 source refers to
page 47 of an operation manual, but that manual has not been independently
obtained and checked \codecite.

\textbf{Boundary: do not reuse the MHM2010 DDS constants for T4.}
Reuse timing fits, stability, provenance and export methods, while keeping
the T4 actuator mapping disabled until the OEM relationship is verified.

\section{Proposed architecture and staged files}
\begin{itemize}
\item \textbf{Pure decoder}: bytes plus a versioned schema produce raw codes,
engineering values and quality flags. No network, file or GUI side effects.
\item \textbf{Read-only acquisition}: a monitoring-only allowlist, request/receive
UTC, monotonic round-trip timing, attempt count, raw frame and parse status.
\item \textbf{Port ownership}: start with one owned listener and serialized
queries; do not assume ephemeral local ports work. Multiple instruments must
not compete to bind the same local port.
\item \textbf{Persistence}: raw frames precede scaled data. Include schema hash,
instrument identity, firmware, sequence and unavailable-channel masks.
\item \textbf{GUI}: separate T4 tab, qtpy/PySide6 and pyqtgraph, in-place curves,
bounded previews, linked axes and crosshair/value displays, following the
AB exemplar \repocite.
\item \textbf{Timing}: explicitly map a genuine T4/reference FITS pair. Do not
assume a SigmaTau or MicroSem label identifies the T4.
\item \textbf{Corrections}: a separate OEM-calibrated adapter, initially disabled.
No state-changing command path in the first acquisition release.
\end{itemize}

The staged \texttt{t4\_channel\_schema\_draft\_v0.1.0.json} records all 41
source-channel identities and provisional gains, without a host address or
personal path. Status fields and unavailable channels are explicitly marked.
It is not an approved calibration table.

\section{Evidence needed before implementation}
\begin{itemize}
\item \textbf{Manual}: operation/remote-command manual, the channel table
referenced as page 47, lock-bit definitions and frequency/drift control sections.
\item \textbf{Identity}: installed firmware/software and screenshots of current
field names, units, values and enabled modes.
\item \textbf{Telemetry}: unedited MONIT replies with matching displays,
including known lock states and installed-option differences if available.
\item \textbf{Timing}: actual FITS names for the T4 and its reference, with an
overlapping recording.
\item \textbf{Access}: connected bracca for the authorized staging directory;
separate explicit approval of a read-only endpoint before any network test.
\end{itemize}

No timeline or credit estimate is assumed. These evidence and acceptance
gates govern readiness.

\section{Appendix: Proposed equations}
The repository's provisional analog conversion and payload accounting are
\codecite:
\[
v_i=g_i c_i,\qquad L_{\mathrm{hex}}=32(3)+8(2)+1=113.
\]
Neither the gains nor status semantics become OEM-verified merely because
they appear in the source.

For a future actuator variable \(u\), define a locally verified fractional
gain \(G\). A small-signal advisory model could then use:
\[
G=\frac{\partial\ln f_{\mathrm{out}}}{\partial u},\qquad
\Delta u\simeq-\frac{y}{G},\qquad
\Delta\dot u\simeq-\frac{r}{G},\qquad
r=\frac{dy}{d(\mathrm{day})}.
\]
These are generic local relationships, not T4 firmware equations. No numerical
gain is assigned. Nonlinear gain, existing steering, discrete updates and
saturation require the actual T4 model.
